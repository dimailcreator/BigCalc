# Stage 23 — accessibility and interaction audit

Status: **browser audit passed**. Stage 22 physical performance validation was accepted from the user's `test-results/stage22-android.json`. Stage 23 changes affect only the application UI and tests; Core semantics and public API are unchanged.

## Checks and changes

| Area                 | Result                                                                                                                                                                                                                                                                                                                                                                        |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Touch targets        | Top navigation is at least 44 × 44 px in the portrait matrix. Expanded keyboard keys at 360 × 640 have a 36 px visual surface but a 44 px hit area inside each cell; pointer hit testing checks both ends of every key. History expression/result actions and numeric Settings inputs are at least 44 px high. Segmented Settings controls have a 44 px effective hit height. |
| Accessible names     | Menu, History, drawer, Back, Backspace, and other icon-only controls expose names. Settings mode abbreviations now announce full names. Each History result describes its saved `deg/rad` and `fac/Gm` metadata.                                                                                                                                                              |
| Keyboard navigation  | Result digits move with arrow keys; `=` and History work through Enter; a History result inserts an atomic `Ans`; drawer and popup trap Tab and restore focus on Escape. Settings and About receive focus after their entry transition; Settings modes can be changed with Space.                                                                                             |
| Modal focus          | Timeout dialog focuses Continue, cycles Tab between its two actions, makes the calculator inert, and restores focus when dismissed.                                                                                                                                                                                                                                           |
| Selection and cursor | The expression caret and selected atomic identifier remain visible; the editor model still owns token boundaries.                                                                                                                                                                                                                                                             |
| Contrast and motion  | Main expression/result exceed 4.5:1 on their background. NumberViewport shows a keyboard focus ring. `prefers-contrast: more` raises History metadata above 4.5:1. Reduced motion removes History layout transitions and preserves focus entry into Settings.                                                                                                                 |
| Text scaling proxy   | At a compressed 320 × 400 CSS viewport, the document allows vertical scrolling to the calculator controls without horizontal overflow. Normal portrait sizes keep the fixed app layout.                                                                                                                                                                                       |

The default History metadata color is fixed by `DESIGN_SPEC.md` at `#5f6672` on `#11151d` (about 3.16:1). The higher-contrast system preference uses the existing muted-text token (about 6.14:1). Primary and secondary content use the specified colors and pass the measured contrast checks. Native TalkBack announcement and Android system font-scale behavior were not measured by the browser audit; the checks above cover DOM names, keyboard behavior, and the compressed CSS viewport.

## Regression coverage

`tests/app/accessibility.spec.js` covers the portrait viewport matrix, effective touch hits, accessible names, keyboard-only paths through Settings and About, atomic selection, focus-visible, contrast preference, reduced motion, and the compressed viewport. `tests/app/calculation-lifecycle.spec.js` covers timeout dialog focus trapping/restoration. Existing editor, navigation, Settings, History, and NumberViewport tests remain part of `npm run check:app`.

The Stage 23 Definition of Done is met: icon-only controls have accessible names, and primary flows work without precise touch gestures. Stage 24 was not started.
