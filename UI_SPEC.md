# BigCalc UI Specification

**Файл:** `UI_SPEC.md`  
**Статус:** Draft 2  
**Область:** пользовательский интерфейс Android-приложения BigCalc и поведение application layer вокруг готового BigCalc Core.  
**Основание:** текущий UI-набросок, согласованные уточнения поведения и продуктовые решения, принятые после проверки HTML/CSS-прототипа.

---

## 1. Назначение документа

Этот документ определяет **как должен вести себя пользовательский интерфейс BigCalc**.

Он задаёт:

- структуру главного экрана;
- модель редактора выражения;
- правила атомарных токенов;
- live-вычисление;
- поведение `=`;
- отображение и прокрутку результатов;
- клавиатуру;
- историю;
- меню и настройки;
- timeout lifecycle;
- взаимодействие с системной клавиатурой и clipboard;
- поведение дополнительных калькуляторов;
- сохранение состояния;
- Android navigation/orientation.

Этот документ **не определяет математическую семантику вычислений**.  
Математическая семантика задаётся `CORE_SPEC.md`.

Этот документ также не фиксирует пока:

- конкретную цветовую палитру;
- точные размеры элементов;
- шрифты;
- длительности анимаций;
- конкретные значения border radius;
- окончательный visual design дополнительных калькуляторов;
- будущий третий формат отображения сверхбольших exponent.

Эти детали задаются отдельным `DESIGN_SPEC.md` и не должны менять семантику, определённую этим документом.

---

# 2. Общие принципы

## 2.1. Core остаётся независимым от UI

UI не должен зависеть от внутренних типов математического ядра.

UI/application layer работает только через публичные контракты Core и собственные application-level abstractions.

В частности, UI не должен напрямую зависеть от:

- `Rational`;
- `Ball`;
- внутренних evaluation graph nodes;
- arbitrary-precision backend;
- конкретных алгоритмов `π`, `Gamma`, `ln`, `exp` и других функций.

---

## 2.2. Основной калькулятор — редактор выражений, а не классический state-machine calculator

Поле ввода содержит выражение по синтаксису BigCalc.

Примеры:

```text
2+3
sin(30)
2^(1/2)
log{2+3}(25)
```

После нажатия `=` результат может визуально занять поле ввода, но математически не превращается в приближённый decimal literal.

---

## 2.3. UI не должен терять математическую точность

Результат вычисления, вставленный:

- после `=`;
- из истории;

представляется в редакторе как атомарный `Ans` token, связанный с конкретным ранее вычисленным выражением.

Displayed decimal text не становится математическим значением этого токена.

---

# 3. Главный экран

Главный экран в обычном состоянии делится сверху вниз на три части:

1. верхняя панель;
2. поле ввода и поле результата;
3. клавиатура.

Концептуально:

```text
┌─────────────────────────┐
│ ≡    history        ⋮   │
├─────────────────────────┤
│ expression              │
├─────────────────────────┤
│ result                  │
├─────────────────────────┤
│                         │
│ calculator keyboard     │
│                         │
└─────────────────────────┘
```

Клавиатура занимает ориентировочно около `2/3` доступной высоты главного экрана.

Точное соотношение определяется responsive layout и не является строгой константой.

---

# 4. Верхняя панель

## 4.1. Кнопка `≡`

Находится слева.

Открывает боковое меню со списком доступных калькуляторов.

В списке в будущем могут находиться, например:

```text
BigCalc
floatX
ИМТ
...
```

Основной BigCalc является одним из calculator modules приложения.

Архитектура бокового меню предусматривает future-action:

```text
+ Добавить калькулятор
```

В первой версии эта action скрыта и недоступна пользователю.

Нельзя оставлять вместо неё невидимую интерактивную область или активную кнопку без реализованной функции.

---

## 4.2. Кнопка истории

Находится после `≡`.

Открывает/закрывает панель истории основного калькулятора.

История существует только у основного BigCalc.

Дополнительные calculator modules собственной истории не имеют.

---

## 4.3. Кнопка `⋮`

Находится справа.

Открывает небольшое меню в правом верхнем углу:

```text
Настройки
О проекте
```

---

## 4.4. Внешний вид кнопок верхней панели

Кнопки верхней панели не имеют отдельного фонового прямоугольника.

Конкретный цвет/iconography задаются visual design layer.

---

# 5. Поле выражения

## 5.1. Представление

Поле выражения всегда одноуровневое.

Не используются визуальные уровни для:

- степеней;
- индексов;
- итераций;
- вложенных логарифмических оснований;
- дробей.

Выражение отображается в синтаксисе BigCalc как линейная последовательность токенов.

---

# 6. Модель Expression Editor

Редактор выражения должен иметь собственную структурированную модель, а не рассматривать всё содержимое как обычную строку.

Минимально различаются:

```text
Text/character tokens
Atomic identifier tokens
Ans tokens
```

---

## 6.1. Обычные элементы

К обычным редактируемым элементам относятся:

- цифры;
- десятичная запятая;
- символы операций;
- отдельные символы скобок;
- другие одиночные допустимые символы синтаксиса.

Между обычными элементами курсор может находиться свободно.

---

## 6.2. Atomic identifier tokens

Многосимвольные имена функций и аналогичные зарегистрированные многосимвольные identifiers являются атомарными блоками.

Например:

```text
sin
cos
tan
ln
log
abs
```

Если в будущем появляются зарегистрированные многосимвольные константы, к ним применяется то же правило.

Для atomic identifier token:

- курсор не может находиться внутри;
- `Backspace` удаляет весь token целиком;
- selection не может захватить только часть token;
- если selection пересекает token, token включается в selection целиком.

Односимвольные константы вроде `π` естественно являются одним элементом.

---

## 6.3. `Ans` token

`Ans` — атомарный объект редактора, который ссылается на результат конкретного ранее вычисленного выражения.

`Ans` используется:

1. после успешного нажатия `=`, когда результат заменяет expression;
2. при вставке результата из истории.

Свойства `Ans`:

- математически ссылается на исходное выражение/результат, а не на отображённый decimal text;
- курсор не может находиться внутри;
- удаляется целиком;
- выделяется только целиком;
- может визуально отображаться как число;
- пока является единственным содержимым expression field, его число можно прокручивать по тем же правилам, что и result field.

---

## 6.4. Cursor

Кроме атомарных блоков курсор может находиться между любыми элементами выражения.

История, keyboard actions и system input вставляют элементы в текущую позицию cursor.

---

## 6.5. Selection

Разрешается выделение диапазона выражения.

Правило атомарности:

```text
если selection пересекает atomic token,
atomic token выделяется целиком
```

Это относится минимум к:

- многосимвольным function tokens;
- многосимвольным identifier tokens;
- `Ans`.

---

# 7. Clipboard input

## 7.1. Paste фильтруется

Текст из clipboard не вставляется как raw text.

Он проходит фильтрацию/tokenization.

Из clipboard принимаются:

- цифры;
- decimal separator `,`;
- поддерживаемые symbols операций;
- `(` и `)`;
- `{` и `}`;
- `[` и `]`;
- зарегистрированные имена функций;
- зарегистрированные имена констант.

Неизвестный текст игнорируется.

Пример:

```text
abc 12+sin(3) xyz
```

даёт допустимую вставку:

```text
12+sin(3)
```

при условии, что `sin` зарегистрирован.

---

## 7.2. Распознавание identifiers

При анализе буквенного текста clipboard должны выбираться зарегистрированные функции/константы.

Неизвестные буквенные последовательности не вставляются.

Если требуется выбрать между несколькими зарегистрированными именами, используется та же детерминированная логика распознавания имён, которая согласована с синтаксисом BigCalc.

---

## 7.3. Paste не должен создавать частичный atomic token

Если clipboard содержит зарегистрированное имя:

```text
sin
```

оно вставляется как один atomic identifier token.

Нельзя получить:

```text
s | i | n
```

как три отдельно редактируемых символа.

---

# 8. Физическая клавиатура

С физической клавиатуры принимаются:

- цифры;
- поддерживаемые символы операций;
- скобки;
- `Backspace`;
- `Enter`.

`Enter` соответствует действию кнопки `=`.

`Backspace` соответствует `⌫`.

Ввод названий функций буквенными клавишами на текущем этапе не является обязательным.

---

# 9. Live calculation

## 9.1. Автоматический расчёт

После изменения expression UI пытается автоматически вычислить текущее выражение.

Вычисление запускается только после debounce.

---

## 9.2. Debounce

После последнего изменения expression:

```text
wait 150 ms
```

После этого старое вычисление для предыдущего expression отменяется/освобождается и создаётся вычисление для нового expression.

Если за эти 150 ms expression снова изменился, timer начинается заново.

---

## 9.3. Старое вычисление

Вычисление, относящееся к уже изменённому expression, не должно продолжать влиять на текущий result field.

При смене expression старый calculation session должен быть отменён/утилизирован application layer.

Это не относится к user freeze из timeout dialog: freeze сохраняет текущую calculation session.

---

# 10. Автоматические ошибки

## 10.1. До нажатия `=`

Если текущее expression:

- синтаксически ошибочно;
- математически выдаёт ошибку;
- не может быть вычислено по domain rules;

то до явного `=` result field остаётся пустым.

UI не показывает автоматическое сообщение об ошибке.

---

## 10.2. После нажатия `=`

При явном `=` ошибка отображается в result field.

Минимально определены пользовательские сообщения:

```text
DivisionByZeroError → "Деление на ноль запрещено"
SyntaxError         → "Ошибка синтаксиса"
```

Mapping остальных Core errors на пользовательские тексты определяется отдельно.

Если после `=` отображается ошибка:

- input field не заменяется;
- history entry не создаётся.

---

# 11. Calculation lifecycle в UI

Для UI различаются минимум следующие состояния:

```text
idle
debouncing
running
pausedByTimeout
frozenByUser
completed
failed
```

Дополнительно application layer может иметь техническое состояние disposed/cancelled для старых session.

---

## 11.1. `pausedByTimeout`

Означает, что Core остановил текущий refinement по soft timeout, но computation можно продолжить.

---

## 11.2. `frozenByUser`

Означает, что пользователь выбрал `Отменить` в timeout dialog.

Это **не** означает уничтожение calculation session.

Состояние сохраняется, но автоматический `continue()` запрещён до нового явного действия пользователя.

---

# 12. Soft timeout

Default soft timeout:

```text
5 seconds
```

---

## 12.1. Первый timeout начального результата

Если live calculation не успевает получить минимальное отображаемое начальное значение за первый 5-second slice:

- предупреждение не показывается;
- calculation переходит в `pausedByTimeout`;
- UI ждёт явного `=`.

---

## 12.2. Нажатие `=` после первого timeout

`=` вызывает:

```text
continue()
```

для той же calculation session.

Никакого пересчёта с нуля быть не должно.

---

## 12.3. Повторный timeout

Если после явного `=` следующий 5-second slice снова завершается timeout до получения минимального начального представления:

показывается timeout dialog:

```text
Вычисление занимает слишком много времени

[Продолжить] [Отменить]
```

Конкретный текст dialog может быть уточнён visual/content design, но семантика кнопок фиксирована.

---

## 12.4. `Продолжить`

Вызывает:

```text
continue()
```

для той же calculation session.

---

## 12.5. `Отменить`

Не уничтожает computation.

Переводит его в:

```text
frozenByUser
```

После этого `=` снова может продолжить computation стандартным механизмом.

---

# 13. Timeout при догрузке дополнительных цифр

Timeout dialog предназначен только для ситуации, когда не удаётся получить минимальное начальное представление требуемого числа.

Если начальное число уже отображается, а timeout произошёл при вычислении следующих цифр:

```text
continue()
```

вызывается автоматически.

Пользователь не получает timeout dialog.

Автоматическое продолжение может повторяться, пока:

- не получены запрошенные дополнительные цифры;
- не возникла hard/resource/error ситуация;
- пользователь не изменил expression;
- calculation не был явно заморожен.

---

# 14. Кнопка `=`

`=` имеет несколько контекстных действий.

---

## 14.1. Если live calculation уже завершён

`=`:

1. использует уже вычисленный результат;
2. не пересчитывает expression с нуля;
3. создаёт history entry;
4. заменяет expression на atomic `Ans` token, связанный с этим результатом.

---

## 14.2. Если calculation находится в `pausedByTimeout`

`=` вызывает:

```text
continue()
```

того же вычисления.

---

## 14.3. Если calculation находится в `frozenByUser`

`=` размораживает computation и продолжает его тем же стандартным механизмом.

---

## 14.4. Если после `=` получена ошибка

Input не заменяется.

History entry не создаётся.

Ошибка показывается в result field.

---

## 14.5. Если после `=` снова произошёл timeout

Показывается timeout dialog.

---

# 15. Поведение после успешного `=`

После успешного `=` expression field содержит только один atomic `Ans` token результата.

Если следующим действием пользователь нажимает:

- цифру;
- decimal comma;

то старый `Ans` удаляется, и expression становится только новым введённым символом.

Примеры:

```text
2+3
=
[Ans: 5]
7
→ 7
```

```text
2+3
=
[Ans: 5]
,
→ ,
```

Для других operators старый `Ans` остаётся частью выражения и operator добавляется относительно cursor по обычным правилам редактора.

---

# 16. Поле результата

Result field показывает:

- текущее автоматически вычисленное число;
- explicit error после `=`;
- `Ошибка отображения`, если текущее представление невозможно по правилам viewport.

Автоматические ошибки до `=` не показываются.

---

# 17. Initial precision

UI не задаёт постоянное фиксированное количество initial digits.

Первоначально запрашивается столько verified digits, сколько необходимо для заполнения доступного result viewport.

То есть initial precision зависит от ширины экрана и текущего формата числа.

---

# 18. Incremental precision

После initial result дополнительные цифры запрашиваются блоками:

```text
+50 digits
```

Запрос следующего блока возникает, когда пользователь прокручивает число к области, для которой verified digits ещё не вычислены.

---

# 19. Placeholder для ещё не вычисленных цифр

Если viewport уже перемещён в область, для которой часть цифр ещё не вычислена, соответствующие позиции отображаются пробелами.

Например:

```text
..1822          E-935
..             E-1127
```

Когда новые verified digits получены, они вставляются на место пробелов без сброса текущей scroll position.

---

# 20. Number viewport

## 20.1. Дискретный scroll

Число нельзя прокручивать на произвольное субсимвольное расстояние.

Scroll выполняется по дискретным позициям.

Один шаг соответствует переходу к соседнему представимому окну числа:

```text
одна цифра исчезает с одной стороны
одна цифра появляется с другой стороны
```

или происходит эквивалентное изменение формата representation.

Scroll не может остановиться «посередине цифры».

---

## 20.2. Границы scroll

Если за текущей границей больше нет цифр, scroll дальше невозможен.

---

## 20.3. Условие scroll

Число можно scroll'ить, когда поле содержит только это число.

Это относится:

- к result field;
- к expression field после `=`, если там находится единственный `Ans` token и нет других элементов.

Если `Ans` участвует в более сложном expression, number-scroll для него не используется.

---

## 20.4. Инерция scroll

Горизонтальный swipe может иметь инерцию: один и тот же physical swipe может приводить к перемещению на несколько digit positions.

Пользовательская настройка:

```text
numberScrollInertia
```

имеет default:

```text
1,6×
```

и применяется сразу после изменения.

Она влияет только на величину логического перемещения при swipe.

Она **не отменяет дискретность NumberViewport**:

- viewport всегда останавливается на целой digit position;
- нельзя остановиться посередине цифры;
- `..`, decimal/scientific transitions и границы scroll продолжают определяться обычными правилами NumberViewport.

Настройка сохраняется между запусками приложения.

---

# 21. Ширина number viewport

Количество доступных visual slots определяется реальной шириной экрана и выбранной typography.

Число занимает фиксированное для данного viewport количество visual slots.

Если exponent становится длиннее, на significand остаётся меньше места.

---

## 21.1. `..`

Индикатор:

```text
..
```

визуально занимает место **одной цифры/одного slot**.

Он означает:

```text
с этой стороны существуют скрытые цифры
```

`..` не является частью математического числа.

---

# 22. Два текущих representation числа

На текущем этапе существуют два вида отображения.

---

## 22.1. Decimal representation

Пример:

```text
317658,71635
```

Используется тогда, когда viewport может показать decimal comma, реально отделяющую целую часть от дробной.

---

## 22.2. Scientific viewport representation

Пример:

```text
..1244815E23
```

Используется во всех случаях, когда decimal comma невозможно показать в текущем viewport.

---

# 23. Семантика `E`

В scientific viewport representation:

```text
E<k>
```

задаёт степень десяти, относящуюся к **последней показанной цифре significand**.

Пример:

```text
..183518E-10
```

означает:

```text
..183518 * 10^-10
```

где последняя видимая цифра находится на позиции `10^-10`.

Таким образом exponent меняется при scroll.

# 24. Примеры scroll

Для:

```text
2^(1/2)
```

возможны окна:

```text
1,4142135623730950
..,4142135623730950
..8016887242096E-31
```

Для:

```text
(40!)^(1/2)
```

возможны:

```text
9032802905233224E8
..905233224086356E2
..0523322408635610,
..35610,17489706286
..0,174897062868113
..,1748970628681132
..7489706286811E-14
..4897062868113E-15
```

Эти примеры иллюстрируют возможность переключения между decimal representation и scientific viewport representation во время scroll.

# 25. Слишком длинный exponent

Теоретически viewport может приблизиться к представлениям вида:

```text
2E4924985285
E815831338383
```

Однако текущая версия UI вводит защитное правило.

Если после размещения exponent и служебных элементов на экране помещается меньше:

```text
2 significant digits
```

result field показывает:

```text
Ошибка отображения
```

Это временное ограничение текущих двух representation.

В будущем планируется третий способ отображения чисел для сверхдлинных exponent.

# 26. Copy результата

Копируется каноническая запись числа.

Пример:


# 28. Keyboard visual groups

Все обычные keyboard buttons имеют rounded-rectangle background.

Исключение:

- top mode row не имеет индивидуального button background.

Существуют как минимум четыре semantic visual groups:

1. обычные клавиши;
2. группа специальных/operator keys;
3. `=`;
4. `AC`.

Точные цвета задаются design layer.

# 29. Кнопка `↕`

Переключает:

```text
compact ↔ expanded
```

Expanded state не сохраняется между запусками приложения.

После нового запуска keyboard находится в:

```text
compact
```

---

# 30. `rad / deg`

Кнопка является persistent toggle.

Состояния:

```text
rad
deg
```

Default:

```text
deg
```

Изменение режима:

1. сразу сохраняется;
2. считается изменением calculation settings;
3. автоматически инициирует пересчёт текущего expression;
4. старое вычисление больше не считается актуальным.

---

# 31. `Gm / fac`

Кнопка является persistent toggle factorial mode.

Состояния:

```text
Gm
fac
```

Default:

```text
fac
```

Изменение режима автоматически пересчитывает текущее expression.

---

# 32. `A1`

На текущем этапе `A1` скрыта.

Функциональность пользовательских функций/констант не входит в текущую UI specification.

---

# 33. `AC`

`AC`:

- очищает expression field;
- очищает result field;
- прекращает/утилизирует текущее calculation, если оно больше не относится к видимому expression;
- возвращает calculator к пустому input state.

`AC` не меняет persistent settings:

```text
deg/rad
fac/Gm
```

---

# 34. `⌫`

Короткое нажатие:

- удаляет один обычный элемент перед cursor;
- если перед cursor находится atomic token, удаляет его целиком;
- если есть selection, удаляет selection целиком.

`⌫` можно удерживать.

При удержании включается autorepeat удаления.

Других long-press действий на `⌫` нет.

---

# 35. Smart bracket buttons

Существуют context-sensitive кнопки:

```text
()
{}
[]
```

Перед вставкой редактор анализирует prefix expression до текущей позиции cursor.

Учитываются:

- незакрытые скобки;
- nesting level;
- текущая позиция cursor.

Если на текущем уровне существует подходящая незакрытая скобка данного типа, вставляется closing bracket.

Иначе вставляется opening bracket.

Пример общего принципа:

```text
prefix has unmatched "(" at current nesting context
→ insert ")"

otherwise
→ insert "("
```

Аналогично для `{}` и `[]`.

Редактор не анализирует только весь expression целиком: решение принимается относительно cursor position.

Поведение при уже синтаксически повреждённом/несогласованном bracket stack может уточняться в реализации, но не должно приводить к crash.

---

# 36. Function keys

Кнопки:

```text
sin
cos
tan
ln
log
```

вставляют соответствующий atomic identifier token и отдельную обычную открывающую скобку `(`. Курсор оказывается после `(`. Это правило действует для пользовательской команды вставки любой доступной приложению функции, включая `exp` и `abs`, даже если для неё нет отдельной кнопки.

Если выделен диапазон, функция оборачивает его: `sin(x+1)` содержит атомарный `sin` и отдельные обычные скобки. После оборачивания курсор находится после `)`. Автоматическая `(` участвует в обычной логике smart brackets и может удаляться отдельно. Paste и восстановление сохранённого выражения только разбирают имеющийся текст: они не добавляют скобку к уже распознанному имени функции.

---

# 37. History

История существует только для основного BigCalc.

---

## 37.1. Что попадает в историю

History entry создаётся только после явного:

```text
=
```

и только если вычисление успешно.

Live calculation сам по себе history entry не создаёт.

Expression с ошибкой после `=` не попадает в историю.

---

## 37.2. History entry

Минимально содержит:

```text
original expression
result reference
displayed result data
evaluation settings
stable history id
```

History не должна зависеть от старого evaluation graph/lazy state.

В UI у каждой history entry показываются использованные при вычислении режимы.

Минимальный формат:

```text
deg · fac
```

или соответствующая комбинация текущих значений:

```text
deg · Gm
rad · fac
rad · Gm
```

Показываемые mode labels отражают `evaluation settings`, сохранённые именно в этой history entry, а не текущие настройки приложения.

---

## 37.3. Открытие истории

Историю можно открыть двумя способами:

1. нажатием кнопки истории;
2. swipe-down из верхней области главного calculator screen.

Точные gesture thresholds, velocity thresholds и animation parameters относятся к design/implementation layer, но жест должен быть достаточно отличим от горизонтального scroll числа.

После открытия истории главный экран трансформируется:

```text
┌──────────────────────┐
│ top bar              │
├──────────────────────┤
│ expression 1         │
│ result 1             │
├──────────────────────┤
│ expression 2         │
│ result 2             │
├──────────────────────┤
│ ...                  │
├──────────────────────┤
│ current expression   │
├──────────────────────┤
│ current result       │
└──────────────────────┘
```

Основной экран сдвигается вниз так, чтобы в нижней части оставались текущие input/result fields.

---

## 37.4. Calculation при открытой истории

Открытие истории не останавливает текущее вычисление.

Calculation продолжает работать.

---

## 37.5. Редактирование при открытой истории

Пока история открыта:

- пользователь может переставлять cursor в текущем expression;
- обычное редактирование expression с calculator keyboard и physical keyboard запрещено;
- вставка expression/result из history разрешена.

History interaction не должна случайно изменять expression другими способами.

После вставки history panel автоматически не закрывается.

Чтобы закрыть историю, пользователь повторно нажимает кнопку истории или использует системный Back.

---

## 37.6. Нажатие на expression history entry

Вставляет исходное expression как обычный редактируемый текст/tokens в текущую позицию cursor.

---

## 37.7. Нажатие на result history entry

Вставляет atomic `Ans` token, связанный с соответствующим history result.

Этот token:

- не раскрывается в decimal literal;
- удаляется только целиком;
- выделяется только целиком.

# 39. Настройки

Settings — отдельный полноэкранный screen.

Настройки расположены горизонтальными блоками/строками.

Если setting имеет стандартно текстово представимое значение:

- используется input field;
- значение валидируется;
- невалидное значение не должно бесконтрольно попадать в application state.

Все settings применяются сразу.

Отдельной кнопки:

```text
Сохранить
```

не требуется.

---

## 39.1. Persistent settings

Минимально persistent:

```text
angle mode
factorial mode
soft timeout
number scroll inertia
```

Текущие defaults:

```text
angleMode = deg
factorialMode = fac
softTimeout = 5 seconds
numberScrollInertia = 1,6×
```

`numberScrollInertia` изменяет только чувствительность/инерцию swipe по NumberViewport и не меняет правило дискретных digit positions.

Допустимый диапазон `numberScrollInertia` — `[0,1; 100]` включительно. Значение по умолчанию остаётся `1,6×`. Некорректный ввод отклоняется и при уходе из поля возвращается последнее принятое значение. Некорректный сохранённый документ настроек отклоняется; при миграции старого ключа недопустимая инерция заменяется значением по умолчанию.

---

## 39.2. Non-persistent UI state

Не сохраняется между запусками:

```text
expanded keyboard state
```

# 41. Android Back

System Back не должен сразу закрывать приложение, если открыт внутренний UI layer.

Back закрывает верхний активный layer.

Например:

```text
popup menu
timeout dialog
history
drawer
settings/about screen
```

закрываются/возвращаются последовательно согласно текущей navigation stack.

Если пользователь находится в другом calculator module:

```text
Back
```

не означает автоматический переход в основной BigCalc.

Navigation назад определяется реальным navigation stack.

# 42. Calculator switching

При переходе между calculator modules состояние текущего calculator сохраняется перед закрытием/деактивацией его screen.

При возврате calculator восстанавливает своё состояние согласно своей persistence policy.

# 43. Дополнительные calculator modules

Другие calculators могут иметь:

- более компактный общий keyboard;
- несколько input fields;
- несколько output fields;
- field labels;
- field descriptions;
- собственную calculation logic;
- собственные errors;
- собственную логику `continue`;
- собственную логику freeze/cancel.

---

## 43.1. Field label

Слева от field может находиться прямоугольный label с названием.

Нажатие на label открывает центральную информационную плашку с описанием field.

---

## 43.2. Что определяет calculator module

Calculator module может определять:

- количество input fields;
- количество output fields;
- названия fields;
- descriptions;
- validation;
- calculation;
- result values;
- error mapping;
- lifecycle своих вычислений;
- поведение `continue`;
- поведение пользовательского freeze/cancel;
- какие данные состояния следует сохранять persistently.

---

## 43.3. Что calculator module не определяет

Calculator module не управляет keyboard definition/layout.

Keyboard остаётся частью общей application UI architecture.

---

## 43.4. History

Дополнительные calculators собственной history не имеют.

# 44. Persistence дополнительных calculators

Persistently сохраняются только те части состояния calculator module, которые сам module объявил сохраняемыми.

Остальное состояние может быть session-only.

# 45. Orientation

Приложение принудительно работает в:

```text
portrait orientation
```

Landscape layout в текущую specification не входит.

На любом устройстве UI ориентируется на вертикальную компоновку, где высота viewport больше ширины.

---

# 46. Responsive behaviour

UI должен адаптироваться к различной ширине/высоте portrait viewport:

- количество visible number slots определяется реально доступной шириной;
- keyboard buttons масштабируются в пределах layout;
- expanded keyboard должна помещаться без смены orientation;
- exponent может уменьшать число visible significand digits.

Точные breakpoints не определены в этой версии specification.

---

# 47. Ошибки отображения и математические ошибки

Следует различать:

## Mathematical/error state

Пример:

```text
Деление на ноль запрещено
Ошибка синтаксиса
```

Это результат evaluation/error mapping.

## Display error

```text
Ошибка отображения
```

Означает, что текущее числовое значение не может быть показано текущими двумя number representations при доступной ширине.

Display error не означает математическую ошибку вычисления.

# 48. Основные инварианты UI

UI считается корректным только если выполняются следующие правила:

1. Displayed decimal text никогда не заменяет математическую ссылку `Ans`.
2. `Ans` и multi-character identifiers остаются atomic.
3. Cursor не может оказаться внутри atomic token.
4. Selection не может захватить часть atomic token.
5. Live calculation не создаёт history entries.
6. History создаётся только после успешного `=`.
7. Ошибка до `=` не показывается автоматически.
8. Ошибка после `=` не заменяет input.
9. `=` не пересчитывает уже существующий calculation с нуля.
10. Первый initial timeout скрыт.
11. Второй timeout после явного `=` показывает timeout dialog.
12. Timeout дополнительных digits автоматически продолжается.
13. User freeze не уничтожает calculation session.
14. Изменение expression уничтожает/отменяет старую неактуальную session.
15. `rad/deg` и `Gm/fac` пересчитывают текущее expression.
16. Additional digits запрашиваются блоками по 50.
17. Невычисленные digits внутри уже открытого viewport показываются пробелами.
18. Number scroll выполняется дискретно.
19. `..` занимает один visual slot.
20. Scientific viewport `E` относится к последней показанной цифре.
21. Clipboard фильтруется; неизвестный мусор игнорируется.
22. Clipboard function names вставляются atomic tokens.
23. Physical Enter эквивалентен `=`.
24. `⌫` может autorepeat.
25. `AC` очищает input и output.
26. Additional calculator modules не имеют history.
27. Calculator module не определяет keyboard layout.
28. Android orientation принудительно portrait.
29. System Back закрывает верхний UI layer, а не обязательно переходит в основной калькулятор.
30. Expanded keyboard не сохраняется между запусками.
31. History можно открыть кнопкой или swipe-down.
32. При открытой history обычное редактирование expression запрещено; разрешены cursor movement и вставка из history.
33. History entry визуально показывает собственные evaluation modes.
34. Number-scroll inertia не нарушает дискретность digit positions.
35. `numberScrollInertia` сохраняется между запусками.
36. `+ Добавить калькулятор` скрыта и недоступна в первой версии.

# 49. Неопределённые детали, не блокирующие реализацию architecture

Следующие вопросы сознательно не фиксируются этой версией:

- окончательные цвета;
- typography;
- exact spacing;
- exact animation timings;
- exact icon set;

# 50. Definition of Done для UI implementation

UI implementation соответствует `UI_SPEC.md`, если:

- основной экран реализует согласованный layout;
- expression editor поддерживает atomic tokens, cursor и selection;
- paste/physical keyboard obey input rules;
- live calculation использует 150 ms debounce;
- stale calculation не влияет на новый expression;
- timeout lifecycle реализован без пересчёта с нуля;
- `=` сохраняет вычисленный state и создаёт `Ans`;
- history работает через expression/result references;
- history открывается кнопкой и swipe-down;
- при открытой history обычное редактирование expression заблокировано, но cursor movement и вставка из history работают;
- history entry показывает режимы, использованные при её вычислении;
- result viewport поддерживает decimal/scientific forms и discrete digit scrolling;
- number-scroll inertia настраивается, сохраняется и не нарушает discrete digit positions;
- lazy additional-digit loading работает блоками по 50;
- missing digits отображаются пробелами и заменяются после refinement;
- keyboard compact/expanded соответствует specification;
- mode toggles persistent и пересчитывают текущее expression;
- user freeze можно продолжить через `=`;
- settings применяются без отдельного подтверждения;
- additional calculator modules интегрируются через общий host и не получают собственную history;
- future-action `+ Добавить калькулятор` не отображается и не доступна в первой версии;
- состояние calculator modules сохраняется согласно declared persistence;
- Android Back и portrait orientation работают согласно specification;
- UI не нарушает mathematical guarantees Core.
